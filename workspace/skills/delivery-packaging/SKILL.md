# Delivery Packaging

Use this skill when work is ready to be handed off, sent, or filed.

Typical triggers:

- quote ready to review
- report ready to send
- contract or paperwork package
- final artifacts need clean naming
- operator needs a short send summary

## Default Contract

Every packaged deliverable should be clear on:

- what the artifact is
- which file is the source
- which file is the preview
- which file is the final
- what should happen next
- whether approval is required before sending

## Default Workflow

1. Inventory the artifacts.
2. Clean up filenames.
3. Confirm which artifact is:
   - source
   - preview
   - final
4. Write a short operator-facing summary.
5. Write a short client-facing draft only if asked or clearly useful.
6. Note filing location or filing intent.
7. Stop before any external send unless approved.

## Rules

- Never assume an artifact is client-ready just because it exists.
- Keep filenames readable and stable.
- Separate packaging from sending.
- If something still needs review, say so clearly.

## Default Output Pattern

```markdown
**Delivery Pack**
- Source:
- Preview:
- Final:
- Clean filenames:
- Filing target:
- Internal summary:
- External draft:
- Approval needed:
```
